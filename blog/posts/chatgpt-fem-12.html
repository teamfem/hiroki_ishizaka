第12回：有限要素法では，なぜ数学的誤差解析が必要なのか

ChatGPTで作る有限要素プログラム入門 第12回
29th August 2026

はじめに――「計算できた」と「正しい近似が得られた」は違う

第1回からここまで，弱形式，P1要素，Jacobian，assembly，3次元， 異方性mesh，debugging，CR・RTまで進んできました．

この連載で何度も現れたのは，

\[ \boxed{ \text{code runs} \not\Longrightarrow \text{correct finite-element approximation} } \tag{1} \]

という事実です．

第4回では，gradient transformを \[ J_T^{-\top} \] ではなく \[ J_T^{-1} \] と誤って実装したコードが，symmetry testとlinear patch testを通過しました． それでもsmooth solutionに対する誤差は期待次数で減りませんでした．

誤差解析の役割
数学的誤差解析は「計算後に付ける理論的説明」ではない．
何が正しい計算結果なのかを，計算前に規定するtest specificationである．

1．最初に「どの誤差を測るか」を決める

有限要素解を \(u_h\)，厳密解を \(u\) と書いても， 「誤差」 という言葉だけでは不十分です．

Poisson問題でも， \[ \|u-u_h\|_{L^2(\Omega)}, \qquad |u-u_h|_{H^1(\Omega)}, \qquad \|u-u_h\|_{L^\infty(\Omega)} \tag{2} \] は異なる量です． またfluxが重要なら \[ \|\nabla u-q_h\|_{L^2(\Omega)} \] や \[ \|\nabla\cdot(q-q_h)\|_{L^2(\Omega)} \] を見ることもあります．

したがって誤差解析の第一歩は， 何を近似したいのか，どのnormで測るのか を決めることです．

2．Céaの補題は「有限要素法の誤差を近似論へ変換する」

Hilbert空間 \(V\) 上のvariational problem \[ a(u,v)=\ell(v) \qquad \forall v\in V \tag{3} \] を考えます． bilinear formが \[ |a(w,v)| \le M\|w\|_V\|v\|_V, \tag{4} \] \[ a(v,v) \ge \alpha\|v\|_V^2, \qquad \alpha>0 \tag{5} \] を満たし，conforming finite-element space \[ V_h\subset V \] を使うとします．

Galerkin solution \(u_h\in V_h\) は \[ a(u_h,v_h)=\ell(v_h) \qquad \forall v_h\in V_h \tag{6} \] を満たし，Céaの補題から \[ \boxed{ \|u-u_h\|_V \le \frac{M}{\alpha} \inf_{v_h\in V_h} \|u-v_h\|_V. } \tag{7} \]

これは重要です． 有限要素誤差の問題を，

\[ \text{PDE solution error} \quad\longrightarrow\quad \text{best approximation error} \]

へ変換しています．

3．対称問題ではenergy normでbest approximationそのものになる

さらに \(a\) が対称かつ正定値で， \[ \|v\|_a:=a(v,v)^{1/2} \tag{8} \] をenergy normとすると，Galerkin orthogonality \[ a(u-u_h,v_h)=0 \qquad \forall v_h\in V_h \tag{9} \] から \[ \boxed{ \|u-u_h\|_a = \min_{v_h\in V_h} \|u-v_h\|_a. } \tag{10} \]

つまりPoisson型の対称coercive problemでは， 有限要素法はenergy normに関して離散空間のbest approximationを与えます．

4．そこで補間誤差解析が必要になる

Céaの補題だけでは \[ \inf_{v_h\in V_h}\|u-v_h\|_V \] の大きさは分かりません． そこで具体的な補間関数 \[ I_hu\in V_h \] を作り， \[ \inf_{v_h\in V_h}\|u-v_h\|_V \le \|u-I_hu\|_V \tag{11} \] と評価します．

shape-regularなsimplicial P1 meshで \(u\in H^2(\Omega)\) なら，標準的に \[ |u-I_hu|_{H^1(\Omega)} \le Ch|u|_{H^2(\Omega)}, \tag{12} \] \[ \|u-I_hu\|_{L^2(\Omega)} \le Ch^2|u|_{H^2(\Omega)}. \tag{13} \]

Poisson problemのenergy normではこれが \[ |u-u_h|_{H^1(\Omega)} = O(h) \tag{14} \] という予測につながります．

5．\(L^2\)で2次になるには追加の数学が要る

P1 finite elementで \[ \|u-u_h\|_{L^2(\Omega)} = O(h^2) \tag{15} \] が得られるのは，単にP1だからではありません．

典型的にはAubin–Nitsche duality argumentを使い， adjoint problemに \[ H^2 \] regularityがあることを仮定します． 例えばconvex polygonでPoisson problemを考える場合などです．

従って

\[ \boxed{ L^2\text{ 2次収束} } \]

という一行の背後には， approximation propertyだけでなく dual problemのregularityが入っています．

数学監査上の注意
「P1だから \(L^2\) 2次」と無条件に書いてはいけない． domain regularity，solution regularity，mesh assumptionsなどを確認する必要がある．

6．収束次数はcode verificationの仕様になる

第4回の2次元Poisson計算では，正しいコードに対して次の相対誤差が得られました．

これは理論の確認であると同時に， コードが想定しているfinite-element methodを実装しているかを調べるverification testです．

7．正しいrateだけでも十分ではない

一方で，

\[ \text{observed rate is correct} \]

だけからコードの正しさを証明することもできません．

pre-asymptotic regimeではrateが揺れますし， quadrature error，round-off error，superconvergence， reference solutionの誤りなどがrateを見かけ上よくすることもあります．

従って第10回でまとめたように，

\[ \text{local invariants} + \text{patch test} + \text{solver residual} + \text{convergence test} \tag{17} \]

を独立に組み合わせる必要があります．

8．nonconforming FEMではapproximation errorだけでは足りない

第11回のCrouzeix–Raviart要素は \[ V_h\not\subset H_0^1(\Omega) \] なので，conforming Galerkin法に対するCéaの補題をそのまま適用することはできません．

discrete energy normを \(\|\cdot\|_h\)， broken bilinear formを \(a_h\) とすると， \(a_h\) が必要な拡張空間上で定義され，右辺もdiscrete test functionに対して意味を持ち，適切なboundedness・discrete coercivityが成立する下でStrang型評価 \[ \boxed{ \|u-u_h\|_h \le C \left[ \inf_{v_h\in V_h} \|u-v_h\|_h + \sup_{0\neq w_h\in V_h} \frac{ |a_h(u,w_h)-\ell(w_h)| }{ \|w_h\|_h } \right] } \tag{18} \] が現れます．

第一項はapproximation error， 第二項はconsistency errorです．

つまりnonconforming methodでは， 「離散空間がよく近似できる」 だけでなく， continuous problemとdiscrete test functionのずれ も評価しなければなりません．

9．mixed FEMではstabilityそのものが誤差解析の一部になる

Raviart–Thomas mixed FEMでは， fluxとscalar variableを同時に近似します． このときerror analysisには Babuška–Brezzi型inf-sup stabilityが必要です．

また第11回で見た \[ \nabla\cdot I_h^{\mathrm{RT}}q = \Pi_0(\nabla\cdot q) \tag{19} \] というcommuting propertyは， divergence errorとpressure / scalar errorを整理する重要な構造になります．

つまりmethodを変えれば， 誤差解析で必要な数学も変わります．

\[ \boxed{ \text{conforming} \to \text{Céa}, \qquad \text{nonconforming} \to \text{Strang}, \qquad \text{mixed} \to \text{inf-sup + commuting structure}. } \tag{20} \]

10．異方性meshでは一個の \(h\) だけでは情報が消える

第6–9回で見たように， 異方性meshでは \[ h_T \] だけでelement geometryを表すことはできません．

2次元P1 interpolationでは，適切なsemi-regularityの下で \[ \boxed{ |u-I_Tu|_{H^1(T)} \le C \sum_{i=1}^{2} h_i \left\| \frac{\partial u}{\partial r_i} \right\|_{H^1(T)} } \tag{21} \] のような方向別評価が使えます． ここで右辺は \[ \left\| \frac{\partial u}{\partial r_i} \right\|_{H^1(T)} \] というfull \(H^1\)-normです．これは第6・8回の表記も数学監査で同じ形に修正しました． この式は2次元P1 Lagrange interpolationに対する代表的な評価であり，正確な定数・幾何仮定は対応するanisotropic interpolation theoremに依存します．

これは \[ h_i \] と \[ \frac{\partial u}{\partial r_i} \] を対応させています．

従って誤差解析は 「meshを細かくすればよい」 ではなく， どの方向をどれだけ細かくすべきか というmesh designの情報を与えます．

11．誤差解析はmesh conditionを発見する

第8回ではshape regularityとsemi-regularityを区別しました．

例えば細長い直角三角形では \[ Q_T=\frac{h_T^2}{|T|} \to\infty \] でも \[ \frac{H_T}{h_T}=2 \] です．

つまりclassical shape regularityを失っても， maximum-angle-based / semi-regular analysisは可能です．

一方でsliver tetrahedronのように， 辺長比だけでは見えないvolume degenerationもあります．

このようにerror analysisは， どの幾何条件が本当に必要か を逆に教えてくれます．

12．discretisation errorとsolver errorを分ける

数学的に定義されたfinite-element solutionを \(u_h\) とし， 数値linear solverが返した近似を \(\widetilde u_h\) とします． すると \[ u-\widetilde u_h = (u-u_h) + (u_h-\widetilde u_h). \tag{22} \]

第一項がdiscretisation error， 第二項がalgebraic / solver errorです．

solver residualが小さいことは主として第二項の管理に関係します． 第一項が小さいことを保証するものではありません．

13．quadrature errorまで入れるとerror budgetが見える

\(u_h\) をexact integrationで定義されるGalerkin solution， \(u_h^Q\) をnumerical quadratureを使ったdiscrete solution， \(\widetilde u_h\) をlinear solverで得た計算解とします． 同じfinite-element space上で定義されているなら，代数的恒等式として \[ \boxed{ u-\widetilde u_h = (u-u_h) + (u_h-u_h^Q) + (u_h^Q-\widetilde u_h). } \tag{23} \]

それぞれ

  • finite-element discretisation error，
  • quadrature / variational-crime error，
  • algebraic solver error

に対応します．

error analysisによって， 「誤差が大きい」 を一個の数字で終わらせず， どこから誤差が入ったか に分解できます．

14．曲領域ではgeometry errorを安易に足してはいけない

curved domain \(\Omega\) をpolygonal domain \(\Omega_h\) で近似すると， continuous solutionとdiscrete solutionが 異なるdomain上の関数 になることがあります．

その場合， \[ u-u_h \] とそのまま引き算する前に， liftやdomain mapを使って同じdomainへ移す必要があります．

従って \[ \text{geometry error} \] を式 (23) に形式的に一項追加するだけでは十分ではありません． この点はExact-curved FEMやisoparametric FEMを比較するときに特に重要です．

15．a priori estimateとa posteriori estimateは目的が違う

a priori estimateは，計算前に

\[ \|u-u_h\| \le C h^p |u|_{H^{p+1}} \tag{24} \]

のような形で， methodのorderやmesh dependenceを説明します．

一方a posteriori estimateは， 実際に得られた \(u_h\) から計算できるestimator \(\eta_h\) を使います． 典型的にはreliability \[ \boxed{ \|u-u_h\| \le C_{\mathrm{rel}}\eta_h } \tag{25} \] と，data oscillationを含むefficiency \[ \boxed{ \eta_h \le C_{\mathrm{eff}} \left( \|u-u_h\|+\operatorname{osc}_h \right) } \tag{26} \] を調べます．

a priori analysisはmethod designと収束理論， a posteriori analysisはcomputed solutionのadaptivityやerror controlに向いています．

16．a posteriori estimatorとrigorous certificateも同じではない

式 (25) に未知または非常に粗い \[ C_{\mathrm{rel}} \] が残る場合， estimatorは有用でも，そのままrigorous numerical certificateとは限りません．

例えばPoisson problem \[ -\Delta u=f, \qquad u|_{\partial\Omega}=0 \] について，ここではgradient-like fluxの符号規約 \[ \sigma=\nabla u, \qquad \nabla\cdot\sigma+f=0 \] を採用します． conforming approximation \(v_h\in H_0^1(\Omega)\) と， equilibrated flux \[ \sigma_h\in H(\mathrm{div};\Omega), \qquad \nabla\cdot\sigma_h+f=0 \tag{27} \] が得られれば，hypercircle identityから \[ \boxed{ \|\nabla(u-v_h)\|_{L^2(\Omega)} \le \|\nabla v_h-\sigma_h\|_{L^2(\Omega)}. } \tag{28} \]

このように定数が明示されたguaranteed boundまで進むと， 「誤差を推定する」 から 「誤差を保証する」 へ一段変わります．

17．目的量が重要ならenergy errorだけでは足りない

工学・科学計算では， solution全体より \[ J(u) \] というoutput quantityが重要な場合があります． 例えば平均flux，drag，特定領域の平均値などです．

このとき必要なのは \[ \|u-u_h\| \] だけでなく \[ |J(u)-J(u_h)| \tag{29} \] の評価です．

Dual-Weighted Residual (DWR)では， primal residualをdual solutionによって重み付けし， どのelementのresidualがoutput errorに効いているかを評価します．

つまりerror analysisは 何を正確に計算したいか によって形を変えます．

18．AI生成コードでは理論を「自動テスト」に変える

ChatGPTが書いたFEMコードに対して， 理論は次のような自動testへ変換できます．

つまり論文に書かれたtheoremを， software verificationのacceptance criteriaへ変換できます．

19．収束次数を自動監査する最小コード

import numpy as np


def observed_rates(errors, h_values):
    errors = np.asarray(
        errors,
        dtype=float
    )

    h_values = np.asarray(
        h_values,
        dtype=float
    )

    if len(errors) != len(h_values):
        raise ValueError(
            "errors and h_values must match"
        )

    if np.any(errors <= 0.0):
        raise ValueError(
            "Errors must be positive"
        )

    if np.any(h_values <= 0.0):
        raise ValueError(
            "Mesh sizes must be positive"
        )

    return np.log(
        errors[:-1] / errors[1:]
    ) / np.log(
        h_values[:-1] / h_values[1:]
    )


h_values = 1.0 / np.array([
    4.0, 8.0, 16.0, 32.0
])

L2_errors = np.array([
    1.5818e-1,
    4.2267e-2,
    1.0755e-2,
    2.7009e-3
])

H1_errors = np.array([
    3.7748e-1,
    1.9438e-1,
    9.7926e-2,
    4.9056e-2
])

print(
    observed_rates(
        L2_errors,
        h_values
    )
)

print(
    observed_rates(
        H1_errors,
        h_values
    )
)

出力は概ね

\[ 1.904,\ 1.975,\ 1.993 \]

と

\[ 0.958,\ 0.989,\ 0.997 \]

です． ただし，この数字を自動的に PASS へ変換する前に， 理論が要求するregularityとmesh assumptionsを確認する必要があります．

20．誤差解析には「仮定監査」が含まれる

theoremに \[ \|u-u_h\| \le Ch^p \] と書いてあっても， その前には必ずassumptionsがあります．

例えば，

  • solution regularity，
  • domain regularity，
  • mesh geometry，
  • coercivity / inf-sup stability，
  • quadrature exactnessまたはvariational-crime control，
  • boundary approximation，
  • element familyに適したmapping

です．

AIがtheoremの結論だけを拾って 「このコードは2次収束するはずです」 と言っても，仮定が満たされていなければ意味がありません．

数学監査 = theorem + assumptions の監査
結論だけではなく， その評価が適用できる条件をコードとmeshが満たしているか を確認する．

21．第4回のbugを誤差解析の言葉で読み直す

誤った \(J^{-1}\) gradient codeでは， symmetryやrow-sumといった局所algebraic invariantsは残りました． しかし実際に実装されたbilinear formは， 意図したPoisson Galerkin formとは一致していません．

そのため，正しいPoisson finite elementに対する \[ H^1:O(h), \qquad L^2:O(h^2) \] という誤差理論をtest specificationとして適用すると，失敗が見えます．

つまりtheoryは， bugの場所を直接教えなくても，「このコードは目的のmethodではない」と検出する ことができます．

22．誤差解析がないとmesh refinementの意味も分からない

meshを細かくして誤差が減ったとしても，

\[ E_h>E_{h/2}>E_{h/4} \]

だけでは不十分です．

知りたいのは \[ E_h \approx C h^p \tag{30} \] の \[ p \] と， constant \(C\) が何に依存するかです．

異方性meshなら \(C\) がaspect ratioに依存して発散するのか， semi-regular parameterで一様に抑えられるのかも重要です．

誤差解析によって初めて， refinementが何を改善しているのかを説明できます．

23．第12回の結論

有限要素法の数学的誤差解析は， 単に \[ O(h),\qquad O(h^2) \] という収束次数を証明するためだけのものではありません．

それは，

\[ \boxed{ \text{method design} + \text{mesh design} + \text{code verification} + \text{adaptive computation} + \text{certification} } \tag{31} \]

をつなぐ共通言語です．

Céaの補題はdiscrete errorをbest approximationへ変換し， 補間理論はrateを与え， Strang型評価はnonconformityを分離し， inf-sup theoryはmixed methodのstabilityを保証し， anisotropic analysisは方向別mesh designを可能にし， a posteriori / equilibrated-flux analysisはcomputed solutionのerror controlへ進みます．

この連載の結論
ChatGPTは有限要素コードを書くことができる．
しかし， そのコードを信用してよい理由を与えるのは数値解析である．

AIに有限要素法を教えてもらうだけではなく， AIと有限要素法を作りながら， AIが作った近似・実装・説明そのものを数学で監査する． それがこの連載で扱ってきたComputational FEM with AIの基本姿勢です．
