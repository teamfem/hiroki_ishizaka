第4回：2次元P1有限要素コードを数学的に監査する — assembly・境界条件・収束

ChatGPTで作る有限要素プログラム入門 第4回
29th August 2026

はじめに――「正しそうなコード」をどう疑うか

第3回では，2次元三角形P1要素について， reference triangleからphysical triangleへの写像 \[ F_T(\widehat x)=p_0+J_T\widehat x \] と， \[ \nabla\phi_i = J_T^{-\top}\widehat\nabla\widehat\phi_i, \qquad dx=|\det J_T|\,d\widehat x \] をコードへ写しました．

今回は新しい有限要素を導入しません．代わりに，そのコードをどの順番で検査すればよいかを考えます． 有限要素コードのdebuggingでは，Pythonの例外を消すだけでは不十分です． 実装が数学的構造を保存しているかを調べる必要があります．

今回の基本方針
一つのテストに合格しただけではコードを信用しない．
局所構造 → assembly → 境界条件 → patch test → solver residual → convergence の順に，独立な検査を重ねる．

1．監査するモデル問題

第3回と同じく， \[ -\Delta u=f \qquad\text{in }\Omega=(0,1)^2, \tag{1} \] \[ u=0 \qquad\text{on }\partial\Omega \tag{2} \] を考えます．厳密解は \[ u(x,y)=\sin(\pi x)\sin(\pi y), \tag{3} \] 従って \[ f(x,y)=2\pi^2\sin(\pi x)\sin(\pi y). \tag{4} \] です．

有限要素空間は連続P1空間 \[ V_h = \{v_h\in H_0^1(\Omega): v_h|_T\in\mathbb P_1(T) \quad\forall T\in\mathcal T_h\} \tag{5} \] とします．

2．監査は局所要素から始める

三角形 \(T\) の局所剛性行列は \[ K^{(T)}_{ij} = \int_T\nabla\phi_j\cdot\nabla\phi_i\,dx. \tag{6} \] P1要素では \[ K^{(T)} = |T|G_TG_T^{\top}, \qquad |T|=\frac{|\det J_T|}{2}, \tag{7} \] ただし \(G_T\) の第 \(i\) 行は \((\nabla\phi_i)^{\top}\) です．

従って，正しい局所行列には少なくとも \[ (K^{(T)})^{\top}=K^{(T)}, \tag{8} \] \[ K^{(T)} \begin{pmatrix}1\\1\\1\end{pmatrix} = 0 \tag{9} \] が成立します．式 (9) は \[ \phi_0+\phi_1+\phi_2=1 \] というpartition of unityの微分 \[ \nabla\phi_0+\nabla\phi_1+\nabla\phi_2=0 \] に対応しています． 

def audit_local_matrix(Ke, tol=1.0e-12):
    symmetry = np.linalg.norm(Ke - Ke.T, ord=np.inf)
    row_sum = np.linalg.norm(Ke @ np.ones(3), ord=np.inf)

    assert symmetry < tol
    assert row_sum < tol

    return symmetry, row_sum

3．Jacobianを直接監査する

局所行列だけでなく，その前段階にある幾何情報も調べます． \[ J_T= [p_1-p_0,\ p_2-p_0] \tag{10} \] について， \[ \det J_T\neq0 \tag{11} \] でなければ要素は退化しています． 反時計回りのconnectivityを採用するなら \[ \det J_T>0 \tag{12} \] も検査できます．

さらに \[ \nabla\phi_i = J_T^{-\top}\widehat\nabla\widehat\phi_i \tag{13} \] なので， 

J = np.column_stack((
    P[1] - P[0],
    P[2] - P[0]
))

detJ = np.linalg.det(J)

assert detJ > 0.0

invJT = np.linalg.inv(J).T
grads = (invJT @ grad_hat.T).T

assert np.linalg.norm(
    grads.sum(axis=0),
    ord=np.inf
) < 1.0e-12

を使えます．

4．assembly後の大域行列を監査する

Dirichlet境界条件をまだ課していない大域剛性行列を \(A_{\mathrm{full}}\) とします． 各局所行列の行和が0なので， \[ A_{\mathrm{full}}\mathbf 1=0. \tag{14} \] 従って \(A_{\mathrm{full}}\) は正定値ではなく，定数ベクトルをkernelに持つ半正定値行列です．

同次Dirichlet境界節点を除去し，内部自由度 \(I\) に制限した行列を \[ A_{II} \tag{15} \] とすると， \[ A_{II}=A_{II}^{\top}, \qquad z^{\top}A_{II}z>0 \quad(z\neq0) \tag{16} \] です． 

AII = A[np.ix_(interior, interior)]

symmetry = np.linalg.norm(
    AII - AII.T,
    ord=np.inf
)

row_sum_full = np.linalg.norm(
    A @ np.ones(len(nodes)),
    ord=np.inf
)

lam_min = np.linalg.eigvalsh(AII)[0]

print(symmetry)
print(row_sum_full)
print(lam_min)

\(n=8\) のuniform triangulationでは，

\(\|A_{\mathrm{full}}\mathbf1\|_{\infty}\)0.0
\(\lambda_{\min}(A_{II})\)3.0448e-1
\(\kappa_2(A_{II})\)2.5274e1

となります．

5．Dirichlet境界条件は値そのものを検査する

同次Dirichlet条件では，境界節点の有限要素値は \[ u_h=0 \qquad\text{on }\partial\Omega \tag{17} \] でなければなりません． 

boundary_error = np.max(
    np.abs(uh[boundary])
)

assert boundary_error < 1.0e-14

これは単純ですが重要です． 解のplotだけを見ると，境界値を誤って処理していても気付きにくい場合があります． 境界自由度を直接数値で検査すべきです．

6．solver residualと有限要素誤差を混同しない

線形方程式を解いた後， \[ r_I = A_{II}U_I-b_I \tag{18} \] を調べます． \(n=8\) では \[ \|r_I\|_{\infty} \approx 6.94\times10^{-16} \tag{19} \] でした．

しかし，これは \[ u_h\approx u \] を意味しません． 残差が小さいということは，組み立てた離散方程式を正確に解いたことしか示していません． 間違った有限要素行列を高精度で解いてもsolver residualは小さくなります．

区別すべき二つの誤差
solver error：\(A_{II}U_I=b_I\) をどれだけ正確に解いたか．
discretisation / implementation error：その \(A_{II}\) と \(b_I\) が正しい有限要素問題を表しているか．

7．linear patch testを行う

第1回，第3回で見たように， \[ u(x,y)=a+bx+cy \tag{20} \] は三角形P1有限要素空間に厳密に含まれます． そこで \[ -\Delta u=0 \] とし，境界値を厳密解から与えれば， \[ u_h=u \tag{21} \] でなければなりません．

例えば \[ u(x,y)=1+2x-3y \tag{22} \] を使うと，最大節点誤差は

161.7764e-15

となります．これは丸め誤差の水準です．

8．最後に収束次数を確認する

滑らかな解に対して，shape-regularな三角形P1メッシュでは \[ \|u-u_h\|_{L^2(\Omega)}=O(h^2), \qquad |u-u_h|_{H^1(\Omega)}=O(h). \tag{23} \] 従って相対誤差 \[ E_{L^2}^{\mathrm{rel}} = \frac{\|u-u_h\|_{L^2(\Omega)}}{\|u\|_{L^2(\Omega)}}, \qquad E_{H^1}^{\mathrm{rel}} = \frac{|u-u_h|_{H^1(\Omega)}}{|u|_{H^1(\Omega)}} \tag{24} \] についても2次と1次が期待されます．

ここまで来て初めて，「この実装は少なくとも期待されるP1有限要素法の漸近挙動と整合している」と判断できます．

9．わざとバグを入れる：\(J^{-\top}\) を \(J^{-1}\) に変える

AI生成コードで起こりやすい誤りを意図的に入れてみます． 正しいコード 

invJT = np.linalg.inv(J).T
grads = (invJT @ grad_hat.T).T

を， 

invJ = np.linalg.inv(J)
grads = (invJ @ grad_hat.T).T

へ変えます．chain ruleに反するので数学的には誤りです．

10．ところが，間違ったコードもいくつかのテストを通る

このバグは意外に見つけにくいです． なぜなら，間違った \(G_T\) を使っても \[ K^{(T)}=|T|G_TG_T^{\top} \] と作れば行列は対称です．さらに \[ \sum_i\widehat\nabla\widehat\phi_i=0 \] なので，任意の線形変換を掛けても行和0という性質は残ります．

さらに今回のstructured meshでは，この誤った実装でもlinear patch testがほぼ機械精度で通ります．例えば \(n=8\) で最大節点誤差は \[ 2.22\times10^{-15} \] 程度です．

重要
symmetry testにもpatch testにも合格したからといって，コードが正しいとは限らない．

11．収束試験はそのバグを検出する

同じ誤ったコードで \[ u(x,y)=\sin(\pi x)\sin(\pi y) \] を解くと，状況が変わります．

この例は， 収束次数が単なる理論上の飾りではなく，実装を検証するテスト仕様になっている ことを示しています．

12．一つのテストではなく，独立な監査を重ねる

今回の例から，テストには役割分担があることが分かります．

test主に検出するもの限界
local symmetry局所行列の非対称な実装ミス誤った対称行列も通る
row-sum testpartition of unityの破壊誤った線形変換でも残る場合がある
boundary testDirichlet処理内部作用素の誤りは分からない
linear patch test一次式再現性今回の \(J^{-1}\) bugを見逃す
solver residual線形solver離散問題自体の正しさを保証しない
convergence test漸近的な離散化・実装の整合性厳密解またはreference solutionが必要

13．監査コードをassertionとして埋め込む

監査を記事だけで終わらせず，開発中のコードへ組み込むこともできます． 

def audit_element(P, Ke, grads, tol=1.0e-12):
    J = np.column_stack((
        P[1] - P[0],
        P[2] - P[0]
    ))

    detJ = np.linalg.det(J)

    assert detJ > 0.0
    assert np.linalg.norm(
        grads.sum(axis=0),
        ord=np.inf
    ) < tol

    assert np.linalg.norm(
        Ke - Ke.T,
        ord=np.inf
    ) < tol

    assert np.linalg.norm(
        Ke @ np.ones(3),
        ord=np.inf
    ) < tol


def audit_linear_system(A, b, uh, interior, boundary):
    AII = A[np.ix_(interior, interior)]

    assert np.linalg.norm(
        AII - AII.T,
        ord=np.inf
    ) < 1.0e-12

    assert np.linalg.eigvalsh(AII)[0] > 0.0

    assert np.max(
        np.abs(uh[boundary])
    ) < 1.0e-12

    residual = (
        AII @ uh[interior]
        - b[interior]
    )

    assert np.linalg.norm(
        residual,
        ord=np.inf
    ) < 1.0e-10

ただし，これらのassertionをすべて通過しても，前節の例のように収束試験が必要です．

14．ChatGPTには「コードを書け」ではなく「監査せよ」と頼む

Audit prompt
この2次元三角形P1有限要素コードを監査してください．
(1) reference gradientからphysical gradientへの変換が \(J^{-\top}\) になっているか，
(2) \(|\det J|\) と三角形面積の \(1/2\) が正しいか，
(3) 各局所剛性行列が対称で行和0か，
(4) assembly後のfull matrixが定数ベクトルをkernelに持つか，
(5) Dirichlet自由度を除去した行列が対称正定値か，
(6) linear patch testを通るか，
(7) solver residualが十分小さいか，
(8) smooth manufactured solutionで \(L^2\) 2次・\(H^1\) 1次の収束が得られるか，
を数式とコードを対応させながら順に確認してください．

このように質問すれば，ChatGPTを単なるcode generatorではなく， 検査項目を一緒に走査するreviewerとして使えます． ただし，最終判断の基準は有限要素法の数学です．

15．第4回の結論

2次元P1有限要素コードの監査では，

  1. Jacobianとphysical gradientを確認する，
  2. 局所行列の対称性・行和を確認する，
  3. assembly後の大域行列の構造を確認する，
  4. Dirichlet境界値を直接確認する，
  5. linear patch testを行う，
  6. solver residualを確認する，
  7. 最後に相対誤差と収束次数を確認する，

という複数段階のテストが必要です．

今回の最も重要な結果
\(J^{-\top}\) を \(J^{-1}\) と誤って実装しても， 対称性やlinear patch testだけでは見抜けない場合がある． しかし，smooth solutionに対する収束試験では誤差がplateauし，実装の誤りが明確に現れる．

有限要素法の誤差解析は，コードを書いた後の理論的な付録ではありません． 期待される収束率そのものが，実装を検証するための仕様になります．
