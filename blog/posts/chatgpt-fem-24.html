第24回：AI時代に有限要素法をどう設計・検証するか — 数学構造からmethodを選ぶ

ChatGPTで作る有限要素プログラム入門 Season 2 第12回（通算第24回・Season 2最終回）
30th August 2026

はじめに――AIに有限要素法の名前を選ばせない

「このPDEにはどの有限要素法を使えばよいか」とAIに聞くと， P1，Taylor–Hood，DG，Nédélec，RTなど，それらしいmethod名はすぐ返ってきます． しかしmethod名が正しくても， trace，orientation，kernel，boundary condition，geometry，regularityのどれかを外せば， コードは静かに別の問題を解き始めます．

Season 2で実装してきた方法を振り返ると， 有限要素法を選ぶ本当の順序は

\[ \boxed{ \text{PDE structure} \longrightarrow \text{function space} \longrightarrow \text{DoF / trace} \longrightarrow \text{discrete operator} \longrightarrow \text{verification} } \tag{1} \]

です．

この回の原則
AIに「methodを教えてもらう」のではなく， 数学構造からmethodを導き，AIにはその実装候補を作らせ，最後に数学で監査する．

1．method selectionの入力はPDE名ではなく構造である

最初に抽出すべき情報はmethod名ではありません． 少なくとも

\[ \boxed{ \begin{aligned} &\text{differential operator},\\ &\text{energy space},\\ &\text{essential / natural boundary conditions},\\ &\text{conservation law},\\ &\text{kernel / constraints},\\ &\text{geometry and regularity},\\ &\text{quantity to be trusted} \end{aligned} } \tag{2} \]

です．

例えば同じPoisson equationでも， solutionだけ欲しいのか，normal fluxを局所保存したいのか， guaranteed upper boundまで欲しいのかでmethod designは変わります．

2．最初の質問――何がcontinuousであるべきか

finite elementのglobal conformityはtrace continuityの選択です．

spaceglobal structure代表 element
\(H^1\)function traceLagrange
\(H(\operatorname{curl})\)tangential traceNédélec
\(H(\operatorname{div})\)normal traceRaviart–Thomas / BDM
broken \(H^1\)weak/interface couplingDG / CR
broken \(H^2\)vertex + derivative momentsなどMorley

この表を飛ばしてbasis formulaから始めると， vector elementを「vector-valued P1」として実装する典型的な誤りが起きます．

3．DoFは「保存したい情報」から決める

DoFはbasisを決めるための番号ではなく， discrete fieldがelement間で共有する情報です．

\[ \boxed{ \begin{array}{rcl} \text{CR}&:&\displaystyle \int_F v\,ds,\\[2mm] \text{Nédélec}&:&\displaystyle \int_E\boldsymbol v\cdot\boldsymbol t\,ds,\\[2mm] \text{RT}&:&\displaystyle \int_F\boldsymbol q\cdot\boldsymbol n\,ds,\\[2mm] \text{Morley}&:& v(p_i),\ \displaystyle\int_E\partial_n v\,ds. \end{array} } \tag{3} \]

したがって

\[ \boxed{ \text{DoF} \longrightarrow \text{trace invariance} \longrightarrow \text{mapping} } \tag{4} \]

という順に考えます．

4．Piola transformは暗記せずDoF invarianceから導く

affine map \[ F_T(\widehat x)=J_T\widehat x+b_T \] に対し， Nédélecではedge circulationを保存するため

\[ \boxed{ \boldsymbol v = J_T^{-\top}\widehat{\boldsymbol v} } \tag{5} \]

を使います． RTではnormal fluxを保存するため

\[ \boxed{ \boldsymbol q = \frac1{\det J_T} J_T\widehat{\boldsymbol q}. } \tag{6} \]

つまりPiola formulaは「element名に付属する呪文」ではなく， どのintegral DoFをinvariantにしたいかから決まります．

5．operator sequenceを見る――de Rham complexを設計図にする

3次元では

\[ \boxed{ H^1 \xrightarrow{\nabla} H(\operatorname{curl}) \xrightarrow{\operatorname{curl}} H(\operatorname{div}) \xrightarrow{\operatorname{div}} L^2 } \tag{7} \]

に対応して

\[ \boxed{ P_1 \xrightarrow{\nabla} N_0 \xrightarrow{\operatorname{curl}} RT_0 \xrightarrow{\operatorname{div}} P_0 } \tag{8} \]

を選べます．

ここでは「各spaceが高精度か」より

\[ \boxed{ \operatorname{curl}\nabla=0, \qquad \operatorname{div}\operatorname{curl}=0 } \tag{9} \]

がdiscrete levelでも壊れないことが重要です．

6．topologyはincidence matrixとして先に実装する

vertex–edge–face–cell incidence matricesを \[ G,\quad C,\quad D \] とすると

\[ \boxed{ CG=0, \qquad DC=0. } \tag{10} \]

このidentityはgeometryやquadratureに依存しません．

従ってAIが作ったmesh codeを監査するときは， PDEを解く前にinteger arithmeticで式 (10) をtestできます．

7．穴があるならexactnessではなくcohomologyを見る

domain topologyがnontrivialでも式 (10) は成立します． 変わるのは

\[ \boxed{ \ker C/\operatorname{im}G, \qquad \ker D/\operatorname{im}C } \tag{11} \]

です．

tunnelがあればharmonic Nédélec modes， cavityがあればharmonic \(H(\operatorname{div})\) modesが残り得ます．

したがって

\[ \boxed{ \text{complex} \neq \text{global exactness} } \tag{12} \]

をAI auditの基本ルールにします．

8．内積を入れるとHodge–Helmholtz分解になる

incidence matrixにmass matrixを組み合わせると， topologyとmetricが接続されます． 例えば

\[ \delta_h=M_1^{-1}C^{\top}M_2 \tag{13} \]

をdiscrete codifferentialとすれば

\[ \boxed{ N_h^0 = \operatorname{im}G \oplus_{M_1} \mathcal H_h^1 \oplus_{M_1} \operatorname{im}\delta_h. } \tag{14} \]

これがdiscrete Hodge–Helmholtz decompositionです．

Maxwell kernelやStokes pressure robustnessを理解するとき， この分解は単なる抽象論ではなくsolver設計の一部になります．

9．conforming methodを選ぶ理由を明文化する

\(H^1\)-conforming Lagrange methodの最大の利点は

\[ V_h\subset V \tag{15} \]

という単純さです． Galerkin orthogonality， energy minimisation， standard duality argumentを直接使えます．

一方，local conservationやspecial tracesを優先するなら， 別のspaceが必要になります．

つまり

\[ \boxed{ \text{conforming} \text{ はdefaultではなくdesign choice} } \tag{16} \]

です．

10．nonconforming methodではapproximationとconsistencyを分ける

CRやMorleyでは \[ V_h\not\subset V. \] 従って「interpolation errorが小さいからFEM errorも小さい」とは言えません．

Strang型の基本構造は

\[ \boxed{ \text{FEM error} \lesssim \text{approximation error} + \text{consistency error}. } \tag{17} \]

AIがnonconforming methodで最もよく落とすのは第二項です．

11．CRを選ぶならRTとの離散部分積分まで見る

CRのface mean continuityとRTのnormal flux continuityは discrete integration by partsで結びつきます．

この関係により， nonconforming consistency termを \(H(\operatorname{div})\) fieldで制御できます．

\[ \boxed{ \text{CR} + \text{RT} \longrightarrow \text{weak continuity} + \text{flux structure} } \tag{18} \]

methodを単独で見るより，compatible elementとの組を見る方が設計しやすい場合があります．

12．mixed methodを選ぶなら「fluxをunknownにしたい理由」を問う

Poissonを \[ \boldsymbol\sigma=\nabla u, \qquad \nabla\cdot\boldsymbol\sigma=-f \] と書いてRT–P0 mixed methodを使うと， normal fluxとcell balanceがprimary unknownになります．

目的が

\[ \boxed{ \text{local conservation} } \tag{19} \]

なら非常に自然です．

ただしmixed matrixがnonsingularだっただけでは十分ではなく， mesh familyに対するuniform inf–sup stabilityは別に確認します．

13．Stokesでは「stable pair」と「pressure robust」を分ける

incompressible Stokesで必要なのはまずinf–sup stabilityです． しかしvelocity errorがpressureやgradient forcingに汚染されないためには pressure robustnessも重要です．

forcingを

\[ \boldsymbol f = \mathbb P\boldsymbol f + \nabla\phi \tag{20} \]

と分けたとき， velocityが本来反応すべきなのはsolenoidal partです．

したがって

\[ \boxed{ \text{inf--sup stability} \neq \text{pressure robustness}. } \tag{21} \]

AIに「stableなStokes element」を求めるだけでは， この区別は保証されません．

14．boundary conditionもmethod designの一部である

Dirichlet condition一つでも

\[ \boxed{ \text{strong imposition}, \quad \text{Nitsche}, \quad \text{DG numerical flux} } \tag{22} \]

という選択があります．

Nitscheではboundary trace inequalityとpenalty scaling， DGではinterior jump / average / penaltyまで設計対象になります．

15．anisotropic Nitscheでは「\(h^{-1}\)」だけでは足りない

face \(F\subset\partial T\) に対してnormal thicknessを

\[ \boxed{ \ell_{T,F} = \frac{d|T|_d}{|F|_{d-1}} } \tag{23} \]

とすれば，anisotropic boundary scalingをgeometryに合わせて記述できます．

isotropicな \[ \gamma/h \] を無条件で使うより， どのnormal directionを制御しているかを明示する方が安全です．

16．DGではjumpを入れる理由をoperatorから説明する

broken spaceではelementwise integration by partsをすると interface termsが残ります． そこで

\[ \boxed{ \text{jump} + \text{average / numerical flux} + \text{penalty} } \tag{24} \]

を使ってglobal couplingを設計します．

penaltyは「大きければ大きいほど安全」ではありません． coercivityを確保しながらconditioningを壊さないscaleが必要です．

17．hybridisationではglobal unknownの意味が変わる

hybridised DG / mixed methodではelement interior unknownをlocalに消去し， skeleton trace \(\lambda_h\) をglobal unknownにできます．

schematically

\[ \boxed{ S_T = D_T-C_TA_T^{-1}C_T^{\top} } \tag{25} \]

というlocal Schur complementをassembleします．

しかし

\[ \boxed{ \text{hybridisation} \not\Rightarrow \text{global DoFが必ず減る} } \tag{26} \]

です． solverとspace designを分けて評価します．

18．4階問題ではregularityをmethodより先に調べる

Morleyや\(C^0\) interior penaltyを選ぶ前に， biharmonic solutionがどこまでsmoothかを確認します．

Morley energy errorでは例えば

\[ u\in H^{2+\alpha}(\Omega), \qquad 0<\alpha\le1 \]

なら典型的に

\[ \boxed{ |u-I_h^Mu|_{2,h} \lesssim h^\alpha |u|_{H^{2+\alpha}}. } \tag{27} \]

つまりpolynomial degreeだけではrateは決まりません．

19．corner singularityはmesh designの入力である

corner近傍のsingular mode \[ u_s = r^\lambda\Phi(\theta) \] に対し \[ D^m u_s \sim r^{\operatorname{Re}\lambda-m} \] なので，genuine singular modeのSobolev thresholdは

\[ \boxed{ s < 1+\operatorname{Re}\lambda. } \tag{28} \]

regularityが不足するなら， uniform refinementの前にgraded meshや\(hp\)-designを検討します．

20．geometry errorはdiscretisation errorとは別である

curved domainをpolygonで近似するとき，

\[ \boxed{ \text{total error} = \text{discretisation} + \text{geometry} + \text{boundary realisation} + \text{quadrature} } \tag{29} \]

という分解を意識します．

mesh-to-mesh convergenceが綺麗でも， limit problem自体が違えば正しいsolutionへは行きません．

21．Babuška paradoxはmethod validationのbenchmarkになる

4階plate problemではgeometry approximationとnatural boundary operatorが強く結合します．

したがって確認すべきなのは

\[ \boxed{ u_h\text{ が収束するか} \quad\text{ではなく}\quad u_h\text{ が正しいvariational limitへ収束するか}. } \tag{30} \]

Babuška paradoxは， geometry–boundary consistencyを検査する代表的benchmarkとして読めます．

22．curved elementではmapping derivativeの階数を確認する

second-order problemではgradient transformが中心ですが， fourth-order problemではnon-affine map \(F_T\) に対して

\[ \boxed{ D^2(v\circ F_T) = DF_T^{\top} (D^2v\circ F_T) DF_T + \sum_{\ell} (\partial_\ell v\circ F_T) D^2F_{T,\ell}. } \tag{31} \]

つまり \[ D^2F_T \] が新しく現れます．

AIが二階問題のmapping formulaをそのまま四階問題へコピーしていないかを監査します．

23．anisotropyでは「最大径 \(h_T\)」だけを見ない

anisotropic simplexではJacobianのsingular valuesが方向ごとに異なります．

したがって \[ \|J_T\|, \qquad \|J_T^{-1}\| \] だけへ全てを潰すと， directional derivative structureを失う場合があります．

監査すべきなのは

\[ \boxed{ \text{element directions} + \text{operator direction} + \text{Piola scaling} + \text{trace geometry}. } \tag{32} \]

24．shape regularityと他のgeometry conditionsを混同しない

mesh quality conditionは一種類ではありません．

shape regularity， maximum-angle-type conditions， semi-regular conditions， normal-thickness conditionsなどは 同じ仮定の言い換えではありません．

従って

\[ \boxed{ \text{theoremのmesh hypothesis} \quad\text{を}\quad \text{codeのmesh generatorと照合する} } \tag{33} \]

必要があります．

25．収束率だけではmethodの正しさを証明できない

manufactured solutionで \[ O(h),\quad O(h^2) \] が出ても，

  • boundary conditionが違う，
  • orientation signが全meshで偶然cancelしている，
  • wrong methodがその特別解だけ再現している，
  • geometry limitが違う，

可能性があります．

したがって

\[ \boxed{ \text{observed rate} \neq \text{mathematical validation}. } \tag{34} \]

26．定理をunit testへ変換する

AI時代のFEM codeでは， proofで使うidentityをそのままtestへ変換するのが有効です．

mathematicsunit test
unisolvenceDoF matrix = identity
polynomial reproductionpatch test
Piola invarianceedge / face integral preservation
complex property\(CG=0,\ DC=0\)
local conservationcell balance
symmetry / coercivitymatrix symmetry・energy positivity
commuting projectionoperator defectをmachine precisionで確認
hypercircle / equilibrationdivergence target・normal continuity・upper bound

27．AI生成コードはまずalgebraic invariantsで落とす

def structural_audit(mesh, fem):
    assert fem.unisolvence_defect() < 1.0e-12
    assert fem.patch_test_error() < 1.0e-12

    if fem.has_edge_orientation:
        assert fem.edge_orientation_is_global()

    if fem.has_face_orientation:
        assert fem.face_orientation_is_global()

    if fem.has_de_rham_complex:
        assert fem.norm_CG() == 0
        assert fem.norm_DC() == 0

    if fem.has_equilibrated_flux:
        assert fem.normal_jump_norm() < 1.0e-12
        assert fem.divergence_target_defect() < 1.0e-12

PDE convergence testはこの後です． structureが壊れたコードをmesh refinementで救おうとしてはいけません．

28．「コンパイルが通る」をverification level 0と考える

AI codeの検証をlayerに分けると分かりやすくなります．

\[ \boxed{ \begin{aligned} L0&:\ \text{syntax / execution},\\ L1&:\ \text{local algebra},\\ L2&:\ \text{global topology / orientation},\\ L3&:\ \text{variational consistency / stability},\\ L4&:\ \text{convergence},\\ L5&:\ \text{guaranteed error / verified enclosure}. \end{aligned} } \tag{35} \]

「動いた」は \(L0\) に過ぎません．

30．AIへのpromptも数学構造で書く

悪いpromptは

「Poisson方程式をFEMで解くPythonを書いて」

だけです．

より安全なpromptは，例えば

2D simplicial mesh上のPoisson problemを実装する．
trial spaceはconforming \(P_1\)，Dirichlet dataはstrongly imposeする．
local stiffnessはaffine mapから導出し，triangle orientationは \(\det J_T>0\) を確認する．
constant / affine patch test，matrix symmetry，energy convergenceをtestする．
数式とコードで使うsign conventionを最初に一覧化する．

のようにverification contractまで含めます．

31．AIに「証明」をさせるより「証明義務」を列挙させる

AIは長いproofを流暢に生成できますが， 一つのsignやtrace domainを誤ると全体が崩れます．

そこでまず

\[ \boxed{ \text{proof obligations} = \{ \text{unisolvence}, \text{mapping}, \text{consistency}, \text{stability}, \text{approximation} \} } \tag{36} \]

を列挙させ， 各項を独立に監査する方が安全です．

32．「定理→コード→数値」の三角形を閉じる

一つのFEM resultには三つの表現があります．

\[ \boxed{ \text{theorem} \longleftrightarrow \text{implementation invariant} \longleftrightarrow \text{numerical experiment}. } \tag{37} \]

例えばNédélecなら

  • theorem：covariant Piolaがedge circulationを保存する，
  • code：transformed basisのedge integralを比較する，
  • experiment：commuting defectとconvergence rateを見る，

という三角形を閉じます．

33．verificationとvalidationを分ける

ここでは二つの言葉を分けて使います．

\[ \boxed{ \begin{aligned} \text{verification} &:\ \text{discrete method / codeが意図した数理問題を実装しているか},\\ \text{validation} &:\ \text{その数理問題が現実のmodelとして適切か}. \end{aligned} } \tag{38} \]

AIが高精度なsolverを生成しても， boundary conditionやphysical model自体が違えばvalidationは失敗します．

34．error estimateとerror certificateを分ける

asymptotic statement \[ \|u-u_h\| = O(h^p) \] と， specific computationに対する \[ \|u-\widetilde u_h\| \le \eta_h \] は役割が違います．

\[ \boxed{ \text{a priori theory} \quad+\quad \text{a posteriori certification} } \tag{39} \]

の両方があると， 「なぜ収束するか」と「今の計算がどこまで正しいか」を分けて答えられます．

35．fully verified computationでは浮動小数点まで閉じる

guaranteed estimator formulaをdouble precisionで評価しただけでは， strict interval proofにはなりません．

必要なら最後に

\[ \boxed{ \text{outward rounding} + \text{interval arithmetic} } \tag{40} \]

でscalar inequalitiesを閉じます．

重要なのは，rigorのlevelを明示することです．

36．AIが最も危険なのは「もっともらしい中間層」

syntax errorは見つけやすく， 大きな発散も見つけやすい． 難しいのは

\[ \boxed{ \text{動く} + \text{rateもそれらしい} + \text{数学構造だけ少し違う} } \tag{41} \]

ケースです．

例えば

  • RTとNédélecのPiolaを取り違える，
  • CRでconsistency termを落とす，
  • Stokesでdiscrete divergence-freeをpressure-robustと同一視する，
  • Morleyでsmooth manufactured solutionからgeneric regularityを推測する，
  • hypercircleでmean equilibrationをexact equilibrationと呼ぶ，

といった誤りです．

37．Season 2で得たmethod-independent audit sequence

どのfinite elementでも，次の順番で監査できます．

\[ \boxed{ \begin{aligned} 1.&\ \text{continuous problem / sign convention},\\ 2.&\ \text{energy space / trace},\\ 3.&\ \text{local polynomial space / DoFs},\\ 4.&\ \text{mapping / orientation},\\ 5.&\ \text{global conformity or nonconformity},\\ 6.&\ \text{consistency identity},\\ 7.&\ \text{stability / kernel / inf--sup},\\ 8.&\ \text{approximation / regularity / geometry},\\ 9.&\ \text{numerical convergence},\\ 10.&\ \text{a posteriori certification}. \end{aligned} } \tag{42} \]

この順序なら，AIが生成したmethodでも 「どこまで確認済みか」を明示できます．

38．AI用finite-element audit prompt

Audit prompt
このfinite-element methodと実装を，method名や既知の収束率を前提にせず数学構造から監査してください．
(1) continuous PDE，weak form，sign conventionを再導出する，
(2) trial/test spaceと必要なtrace continuityを特定する，
(3) local polynomial spaceとDoFsのunisolvenceを確認する，
(4) affine / curved mappingとDoF invarianceを確認する，
(5) edge / face orientationをglobalに整合させる，
(6) conformingならsubspace inclusion，nonconformingならconsistency termを確認する，
(7) mixed / saddle-point problemならkernelとinf–sup conditionを確認する，
(8) de Rham structureがある場合 \(CG=0,\ DC=0\) とcommuting projectionを確認する，
(9) boundary conditionがstrong / weak / naturalのどれかを区別する，
(10) anisotropic meshでtheoremのgeometry hypothesisとmesh generatorを照合する，
(11) solution regularityが主張する収束率に十分か確認する，
(12) curved domainではgeometry errorとboundary-realisation errorを分離する，
(13) local conservation / pressure robustness / harmonic modesなどproblem-specific structureを確認する，
(14) patch test・operator identity・energy testを収束試験より先に実行する，
(15) guaranteed errorを主張する場合はequilibrationやresidual upper boundを確認する，
(16) fully rigorous computationを主張する場合はroundingまで含めて閉じる，
(17) 最後に「証明済み・数値確認のみ・未確認」の三分類でaudit結果を返す
こと．

39．methodを選ぶ最終式

finite element methodを選ぶ操作を一行で書くなら，

\[ \boxed{ \mathcal M_h = \mathcal M_h( \text{operator}, \text{trace}, \text{topology}, \text{geometry}, \text{regularity}, \text{conservation}, \text{target} ). } \tag{43} \]

methodはPDE名だけの関数ではありません．

そしてAIの役割は

\[ \boxed{ \text{candidate generation} + \text{symbolic / coding assistance} + \text{automated tests} } \tag{44} \]

であり， mathematical acceptance criterionは人間側が明示します．

40．Season 2の結論――コードに数学構造を埋め込む

Season 2では，nodal P1から離れて CR，RT，mixed Poisson，Stokes，Nitsche，DG，Morley，Nédélec， de Rham complex，equilibrated fluxまで実装しました．

一見ばらばらなmethodsに共通していたのは

\[ \boxed{ \begin{aligned} &\text{DoF},\\ &\text{trace},\\ &\text{orientation},\\ &\text{operator compatibility},\\ &\text{stability},\\ &\text{geometry},\\ &\text{certification} \end{aligned} } \tag{45} \]

です．

AIがコード生成を高速化するほど， この数学構造を先に固定する価値は大きくなります．

\[ \boxed{ \text{AI-generated FEM} \quad\text{を}\quad \text{mathematically auditable FEM} \quad\text{へ}. } \tag{46} \]
Season 2 最終原則
有限要素法は「basis functionを並べる技術」ではない． 連続問題の構造を，有限次元のDoF・operator・orientation・energyへ移す技術である．
